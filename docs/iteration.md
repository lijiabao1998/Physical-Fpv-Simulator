# 設計迭代（第 7 階段）

真實研發改一個設計時，會先寫清楚改了什麼（工程變更），再用和原設計完全相同的方法重新評估，最後把差異和它的不確定度一起交給做決定的人。`fpvsim compare` 照這個流程進行。

## 版本檔：只寫變更

```toml
schema = "fpvsim.build/1"

[meta]
extends = "ref-5in-6s-freestyle.toml"      # 基準設計（相對路徑以本檔為準）
id = "ref-5in-6s-freestyle-actioncam-b"
name = "版本 B：相機裝在上板前端、電池後移"
change = "加掛全尺寸運動相機（上板前端），電池後移 20 mm"
remove_parts = []                          # 要移除的零件名稱

[[parts]]                                  # 同名：取代基準的零件（這裡是把電池往後移）
name = "battery"
uses = "battery"
position = { value = [-20, 0, -46], unit = "mm" }

[[parts]]                                  # 新名稱：新增零件
name = "action_camera"
component = "../components/payloads/generic-action-camera-full.toml"
position = { value = [40, 0, -60.5], unit = "mm" }
```

合併規則：

- `[[parts]]` 依名稱合併：同名的零件取代基準的零件，新名稱則新增。
- `remove_parts` 移除零件。
- `[components]`、`[electrical]`、`[flight_controller]` 以鍵覆蓋。
- 版本可以再被別的版本 `extends`；循環引用會報錯。
- 報告列出每個版本的完整演進（lineage），輸入檔雜湊涵蓋整條鏈上的所有檔案。

## 零件阻力疊加

零件可以帶自己的阻力面積 `cda_x`、`cda_y`、`cda_z`，寫在零件檔的 `[params]` 或直接寫在 `[[parts]]` 裡。機體的阻力面積 = 機架的值 + 各零件的值（drag buildup）。這是一階估計：零件之間的干擾不計，零件的安裝角度也不計。

## 成對比較

用兩次獨立的蒙地卡羅比較兩個版本時，差異會被兩邊各自的抽樣雜訊淹沒。fpvsim 的抽樣以「物品」為單位，每個參數的亂數流由（種子，物品身分）決定：

- 零件檔的參數以零件檔的 id 為身分。同一個零件檔在各版本中取相同的值；換成另一個零件檔，即使數值一樣，也視為不同的物品，誤差彼此獨立。
- 其他參數（行內零件、電氣、安裝位置的不確定度……）以名稱、數值、不確定度與來源為身分。數值不變就取相同的值，改了數值就是新的物品。

這就是「共同亂數」（common random numbers）方法，版本差異是逐組直接算出來的。`tests/test_variants.py` 的檢查：

- 版本 A 與基準的全備重量差，**每一組都恰好等於**該組抽到的相機質量加相機座質量。
- 換成另一個電池零件檔時，兩個版本的電池誤差獨立，差異的標準差約為單一電池的 √2 倍。

**要注意：** 成對抽樣只消去共有參數的「抽樣雜訊」，不會消去它們對變更「大小」的影響。例如多 165 g 要多耗多少電，取決於槳的效率；所以續航差的區間主要來自槳與馬達的不確定度，而不是相機本身。比較報告第 3 節的「差異的敏感度」逐一列出影響差異的參數，第 8 節的量測建議由它產生。

## 安裝位置的不確定度

零件可以寫 `position_u = { value = [ux, uy, uz], unit = "mm", source = ..., note = ... }`，表示安裝位置的標準不確定度。例如電池每次綁的位置都不同，相機座的安裝也有誤差。它們會產生 `<零件>.offset_x/y/z` 參數，參與蒙地卡羅，所以重心相關的規格符合機率會包含它。

## 槳葉間隙檢查

比較報告會檢查每個零件（機架與動力系統以外）：如果它在俯視圖上落在某顆槳的槳盤範圍內，而且離槳平面不到 10 mm，就列為問題。這個檢查抓到過最初版本 B 的相機座離前槳的槳平面只有 3 mm。

## 比較內容

```bash
fpvsim compare data/builds/ref-5in-6s-freestyle.toml \
               data/builds/ref-5in-6s-freestyle-actioncam-a.toml \
               data/builds/ref-5in-6s-freestyle-actioncam-b.toml \
               --fc data/fc/acro-5in-baseline.toml
```

第一個檔是基準，其餘是要比較的版本。每個版本都會：

1. 列出相對基準的設計變更：新增、移除、移動的零件，更換的零件檔或規格，新增、移除或改了數值的參數。
2. 做靜態分析與規格符合度，使用成對蒙地卡羅，並對版本差異做 ±1σ 敏感度分析。
3. 以相同飛控設定（基準增益）、相同腳本與種子試飛（每個版本一次標稱值飛行，沒有不確定度）。
4. 執行調參研究：先看基準增益在新機體上的表現，再找出它自己的建議增益。

所有版本必須使用同一份規格（需求與試驗條件），否則 `fpvsim compare` 會在分析前拒絕。

選項 `--no-fly`、`--no-tune` 可以跳過較慢的部分。完整比較三個版本約需 10 分鐘。
