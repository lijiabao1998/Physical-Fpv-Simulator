# 設計迭代（第 7 階段）

真實研發改一個設計時，會先寫清楚改了什麼（工程變更），再用和原設計完全相同的方法重新評估，最後把差異和它的不確定度一起交給做決定的人。`fpvsim compare` 照這個流程進行。

## 版本檔：只寫變更

```toml
schema = "fpvsim.build/1"

[meta]
extends = "ref-5in-6s-freestyle-actioncam-a.toml"   # 前一個版本（相對路徑以本檔為準）
id = "ref-5in-6s-freestyle-actioncam-c"
name = "版本 C：相機綁在電池上方、移到重心正上方"
change = "相機與相機座往後移 24 mm，位於重心正上方"
remove_parts = []                                   # 要移除的零件名稱

[[parts]]                                           # 同名：取代前一版的零件（這裡是把相機往後移）
name = "action_camera"
component = "../components/payloads/generic-action-camera-full.toml"
position = { value = [6, 0, -98.5], unit = "mm" }
mounted_on = "camera_mount"                         # 相機鎖在相機座上，跟著相機座移動
position_u = { value = [1, 1, 1], unit = "mm", source = "estimate" }   # 相對相機座的誤差
```

新名稱的 `[[parts]]` 則是新增零件。

合併規則：

- `[[parts]]` 依名稱合併：同名的零件取代基準的零件，新名稱則新增。取代是整筆的：要沿用的設定（`position_u`、`mounted_on`、阻力面積……）也要重寫，否則就會消失（比較報告會把它們列為「移除參數」）。
- `remove_parts` 移除零件。
- `[components]`、`[electrical]`、`[flight_controller]` 以鍵覆蓋。
- 版本可以再被別的版本 `extends`；循環引用會報錯。
- 報告列出每個版本的完整演進（lineage），輸入檔雜湊涵蓋整條鏈上的所有檔案。

## 零件阻力疊加

零件可以帶自己的阻力面積 `cda_x`、`cda_y`、`cda_z`，寫在零件檔的 `[params]` 或直接寫在 `[[parts]]` 裡（drag buildup）。零件的阻力作用在零件自己的位置，所以裝得比重心高的相機在前飛時會產生抬頭力矩。機架本身的阻力作用在機架上的固定點（機架檔的 `drag_center`），不會跟著重心移動：加掛相機讓重心升高後，機架阻力位於重心下方，前飛時產生低頭力矩。這是一階估計：零件之間的干擾、零件的安裝角度，以及電池移動造成的機架阻力中心變化都不計。

## 成對比較

用兩次獨立的蒙地卡羅比較兩個版本時，差異會被兩邊各自的抽樣雜訊淹沒。fpvsim 的抽樣以「物品」為單位，每個參數的亂數流由（種子，物品身分）決定：

- 零件檔的參數以零件檔（id 加上檔案內容的雜湊）為身分；用零件檔做成的 `[[parts]]` 零件再加上零件名稱。同一個檔案、同一個零件名稱在各版本中取相同的值。換成另一個零件檔，或複製零件檔後修改了內容（即使沒改 id），都視為不同的物品，誤差彼此獨立。同一個零件檔用在兩個不同名稱的零件上（例如兩顆同型相機），也是兩個物品。
- 其他參數（行內零件、電氣、安裝位置的不確定度……）以名稱、數值、不確定度與來源為身分。數值不變就取相同的值，改了數值就是新的物品。
- 要「移動」一個零件，保留它的名稱、只改位置；改了名稱就是換了一個零件。

這就是「共同亂數」（common random numbers）方法，版本差異是逐組直接算出來的。`tests/test_variants.py` 的檢查：

- 版本 A 與基準的全備重量差，**每一組都恰好等於**該組抽到的相機質量加相機座質量。
- 換成另一個電池零件檔時，兩個版本的電池誤差獨立，差異的標準差約為單一電池的 √2 倍；複製後修改了內容的零件檔也是如此。

**要注意：** 成對抽樣只消去共有參數的「抽樣雜訊」，不會消去它們對變更「大小」的影響。例如多 165 g 要多耗多少電，取決於槳的效率；所以續航差的區間主要來自槳與馬達的不確定度，而不是相機本身。比較報告第 3 節的「差異的敏感度」逐一列出影響差異的參數（以亂數流分組，和蒙地卡羅的配對方式一致），第 8 節的量測建議由它產生。

## 安裝位置的不確定度

零件可以寫 `position_u = { value = [ux, uy, uz], unit = "mm", source = ..., note = ... }`，表示安裝位置的標準不確定度。例如電池每次綁的位置都不同，相機座的安裝也有誤差。它們會產生 `<零件>.offset_x/y/z` 參數，參與蒙地卡羅，所以重心與槳葉間隙相關的規格符合機率會包含它。

疊裝的零件寫 `mounted_on = "<母零件>"`：相機座綁在電池上時，電池綁偏了，相機座也跟著偏。這時零件的位置誤差是母零件的誤差加上自己的 `position_u`（相對母零件）。如果把它們當成各自獨立，重心的分散會被低估。

## 槳葉間隙（規格 R7）

每個零件（機架與動力系統以外）要在俯視圖上離槳盤邊緣 3 mm 以上（槳的半徑公差與馬達軸偏擺），或離槳平面 10 mm 以上（槳葉受力上翹與振動）。「槳葉間隙餘量」是最差的零件在較容易的方向上還能移動多少，負值表示兩條都不滿足。它是每組蒙地卡羅樣本都計算的指標，所以會包含安裝位置的不確定度：

- 只看標稱位置是不夠的。版本 B 最初的相機座只比前槳槳盤多 0.4 mm，電池後移 20 mm 後後緣只比後槳槳盤多 1.1 mm，兩者都只高出槳平面 3 mm；標稱值就不符合規則，加上電池綁帶的誤差更是每一組樣本都不符合。
- 基準機的電池離槳盤邊緣約 10 mm，標稱值有 5 mm 以上的餘量；但電池綁偏時仍有約 2% 的樣本進入 3 mm 範圍。

## 比較內容

```bash
fpvsim compare data/builds/ref-5in-6s-freestyle.toml \
               data/builds/ref-5in-6s-freestyle-actioncam-a.toml \
               data/builds/ref-5in-6s-freestyle-actioncam-b.toml \
               data/builds/ref-5in-6s-freestyle-actioncam-c.toml \
               --fc data/fc/acro-5in-baseline.toml
```

第一個檔是基準，其餘是要比較的版本。每個版本都會：

1. 列出相對基準的設計變更：新增、移除、移動的零件，更換的零件檔或規格，新增、移除或改了數值的參數。
2. 做靜態分析與規格符合度，使用成對蒙地卡羅，並對版本差異做 ±1σ 敏感度分析。
3. 以相同飛控設定（基準增益）、相同腳本與種子試飛（每個版本一次標稱值飛行，沒有不確定度）。
4. 執行調參研究：先看基準增益在新機體上的表現，再找出它自己的建議增益（建議值落在掃描範圍邊緣時，掃描會自動擴大）。

所有版本必須使用同一份規格（需求與試驗條件），否則 `fpvsim compare` 會在分析前拒絕。

選項 `--no-fly`、`--no-tune` 可以跳過較慢的部分。完整比較四個版本約需 20–30 分鐘（4 核心）。

## 這次的範例：加掛運動相機

| 版本 | 變更 |
|---|---|
| base | 參考機（不掛相機） |
| A | 全尺寸運動相機綁在電池前端，電池不動（最快的改法） |
| B | 相機裝在上板前端，電池後移 20 mm 讓重心回到推力中心 |
| C | 從 A 改：相機與相機座往後移到重心正上方，電池不動 |

C 的演進是 base → A → C：它 `extends` 版本 A，報告的演進欄會列出整條鏈。
