# 研發方法

這份文件說明 fpvsim 用什麼方法讓結果可信、可追溯、可重現。它對應真實工程研發中的做法，而不是遊戲或動畫的做法。

## 1. 驗證與確認（V&V）

兩件事要分開談：

- **驗證（verification）**：程式有沒有正確解出它宣稱的方程。用解析解、守恆律、極限情況和收斂測試檢查，全部寫在 `tests/` 中，每次修改都要通過。
- **確認（validation）**：方程本身符不符合現實。只能用實測數據比對，例如推力台數據、實機 Blackbox log。

目前所有模型都已**驗證**。**確認**只有一部分：通用槳的靜態係數與它們隨轉速（雷諾數）的變化，已和同類槳的公開推力台數據逐點比對（`fpvsim validate-prop`，見 [models.md](models.md#校正與驗證fpvsim-validate-prop)）；其他零件數據仍是估計值，尚未確認。報告會明白寫出這一點。

測試抓到過的實際問題：

- **系統識別的覆蓋率檢查**：推力台雜訊通常和讀數成正比，一般最小平方法的標準誤差會因此低估約 1.7 倍。現在改用 HC3 異質變異穩健標準誤差，兩種雜訊結構都通過。
- **濾波器截止頻率**：常見的 PT1 增益公式 k = dt/(RC + dt) 讓「100 Hz」濾波器在 4 kHz 迴圈中實際的 −3 dB 點落在 93 Hz。現在依離散轉移函數精確求解增益。

## 2. 參數出處

每個參數都是一筆紀錄：數值、單位、來源類別、標準不確定度、分布、引用或說明。缺少來源就無法載入。

| 來源 | 意義 |
|---|---|
| `measured` 實測 | 自己量的，附量測紀錄 |
| `standard` 標準值 | 定義值或標準（ISA、g₀） |
| `nominal` 標稱值 | 零件的定義規格，例如 5.1 吋槳的直徑、標示的 C 數 |
| `datasheet` 規格書 | 廠商規格，必須附引用 |
| `literature` 文獻 | 論文或教科書，必須附引用 |
| `derived` 模型推導 | 由其他參數經模型計算，例如 BEMT 得到的槳係數 |
| `estimate` 工程估計 | 依零件級距的工程判斷，必須附不確定度 |
| `synthetic` 合成數據 | 只能用在驗證測試，不能出現在設計中 |

`fpvsim check` 會檢查：估計值沒有不確定度、規格書或文獻沒有引用、設計中出現合成數據，都會報警告。

陣列數據（槳葉弦長分布、OCV 曲線、槳的係數表）以整張表標示來源。槳的係數來自同類槳的平均或 BEMT 時，不確定度由兩個乘數代表：推力係數 `prop.ct_scale` 與靜態效率因數 `prop.fm_scale`；功率係數乘數由兩者導出（Cp ∝ ct_scale^1.5 / fm_scale），因為推力與功率的誤差是相關的，各自獨立抽樣會產生物理上不可能的效率。效率因數在整個雷諾數範圍內限制在 0.8 以下（沒有旋翼比這更有效率）。實測自己的槳時，改用擬合得到的 Ct、Cp 不確定度。BEMT 的輸入只在載入時計算一次，不抽樣。

## 3. 不確定度

依 GUM（JCGM 100:2008）慣例：

- `u` 是**標準不確定度**（1σ），與數值同單位；`u_rel` 是相對值。
- 分布可以是 `normal` 或 `uniform`。均勻分布的 `u` 仍是標準差，半寬為 √3·u。
- 數值為正的參數，抽樣時截斷在正值。

傳遞方法採 GUM Supplement 1（JCGM 101:2008）的蒙地卡羅：每組樣本都重跑完整分析，所以非線性和不可行的情況（例如推力不足無法懸停）都會如實反映。

每個參數的亂數流由（種子，物品身分）決定，與其他參數無關。物品身分的規則見 [iteration.md](iteration.md)：零件檔的參數以零件檔（id 與檔案內容）加上零件名稱為身分，其他參數以名稱、數值、不確定度與來源為身分。因此比較兩個設計版本時，兩個版本共有的物品在第 i 組樣本中取相同的值（共同亂數），版本差異是逐組直接算出來的，不會被兩次獨立抽樣的雜訊淹沒。

假設與限制：

- 參數之間視為**獨立**。
- 同型零件（四顆馬達、四支機臂）**共用一個參數**，視為完全相關，因此不會產生不對稱。
- 零件的安裝位置可以標示不確定度（`position_u`），以位移參數參與抽樣；疊裝的零件（`mounted_on`）會跟著母零件一起移動。

規格的**符合機率**是樣本中滿足需求的比例。所有樣本都符合時，報告以三法則給出 95% 信心的單邊界限（失敗機率 < 3/n），而不是寫 100%。

敏感度採**單因子 ±1σ**（龍捲風圖）。各參數對續航、推重比、懸停油門的相對影響加總後排序，就是報告中的「建議優先量測」清單，對應真實研發中決定先量哪個數據的依據。

## 4. 單位與座標系

- 程式內部一律使用 SI 單位（kg、m、s、A、V、Ω、rad、N、W、C）。單位只在讀檔與顯示時換算，支援的單位全部明列在 `units.py`，打錯字會直接報錯。
- 機體座標為 **FRD**（x 前、y 右、z 下），與飛控韌體和航太慣例一致。原點在馬達安裝面上的馬達中心。
- 慣性張量採張量形式 I = ∫(|r|²E − r rᵀ)dm，非對角項是負的慣性積。
- 槳係數採標準螺旋槳慣例，n 的單位是每秒轉數：T = Ct·ρ·n²·D⁴，P = Cp·ρ·n³·D⁵。

## 5. 系統識別

`sysid.py` 從測試數據辨識模型參數，每個擬合都是對參數為線性的最小平方問題：

| 測試 | 模型 | 得到 |
|---|---|---|
| 推力台（靜態） | T = kT·ω²，Q = kQ·ω² | Ct₀、Cp₀ |
| 推力台（靜態，含雷諾數） | log Ct = log Ct_ref + n_T log(Re/Re_ref)，FM 同理 | Ct、FM 在 Re_ref 的值與兩個指數 |
| 無槳空載，多個電壓 | V − I·Rm = Ke·ω；I₀ = a + b·ω | Kv、空載損耗模型 |
| 有負載 | V = Ke·ω + R·I | Ke、迴路電阻 |

標準誤差使用 HC3 三明治估計量（MacKinnon & White, 1985），在雜訊隨讀數變大時仍然正確。測試數據的 CSV 標頭必須帶單位，格式為 `名稱 [單位]`。

## 6. 可重現性

每份報告記錄：

- 程式版本與 git commit（工作區有未提交修改時會註明）
- 所有輸入檔的 SHA-256 雜湊
- 蒙地卡羅樣本數與隨機種子

用相同的 commit、輸入和種子重跑，會得到相同的數字。

## 7. 數據與智慧財產政策

- **零件庫不使用品牌與產品名稱。** 零件庫中的零件都是通用級距（例如「2306 級 1750KV 馬達」），不代表任何特定產品。
- **不複製第三方測試資料表。** 廠商推力表、槳資料庫等可能受著作權、資料庫權利或使用條款保護，不整份收錄在儲存庫中。使用者可以匯入自己量測的數據。
- **規格書與公開測試的數值**屬於事實資訊，可以個別引用，但必須附出處，而且不大量轉錄整份資料表。`data/validation/` 的確認數據依此收錄：每個來源只取幾個點（推力台測試 3–4 點、風洞檔案隔列取點），每一點記錄來源網址與它在原始資料中的位置；受測物的品牌與型號只出現在引用中，用來標示數據是哪一款槳量的。通用零件的數值由這些點擬合（同類平均），不等於任何一款產品。
- **物理模型依公開的方程自行實作。** 方程與演算法本身不受著作權保護；引用的教科書與論文列在 `docs/models.md`。
- **不複製 GPL 等授權的程式碼。** Betaflight 採 GPL-3.0。本專案的飛控模型依公開資料描述的行為自行撰寫，只使用公開的數值常數（PID 尺度）與曲線性質（Actual rates），沒有複製其原始碼；對應關係列在 [flight-sim.md](flight-sim.md#和-betaflight-的關係)。
- **授權：** 本專案採 MIT 授權（見 `LICENSE`）。因此不能併入 GPL 程式碼；若日後需要移植 GPL 程式碼，必須另行處理授權相容性。
