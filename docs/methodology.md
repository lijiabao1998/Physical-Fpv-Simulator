# 研發方法

這份文件說明 fpvsim 用什麼方法讓結果可信、可追溯、可重現。它對應真實工程研發中的做法，而不是遊戲或動畫的做法。

## 1. 驗證與確認（V&V）

兩件事要分開談：

- **驗證（verification）**：程式有沒有正確解出它宣稱的方程。用解析解、守恆律、極限情況和收斂測試檢查，全部寫在 `tests/` 中，每次修改都要通過。
- **確認（validation）**：方程本身符不符合現實。只能用實測數據比對，例如推力台數據、實機 Blackbox log。

目前所有模型都已**驗證**，但**尚未確認**，因為零件數據都是估計值。報告會明白寫出這一點。

主要的驗證測試：

| 對象 | 測試 | 檔案 |
|---|---|---|
| 大氣 | 與 ISO 2533 標準大氣表比對（0、1000、3000、11000 m） | `test_atmosphere_mass.py` |
| 質量性質 | 箱體與圓柱慣性對數值積分；平行軸定理；旋轉不改變主慣性矩；慣性三角不等式 | `test_atmosphere_mass.py` |
| 馬達 | 空載轉速解析解；扭矩平衡；能量守恆（電功率 = 銅損 + 鐵損與摩擦 + 軸功率） | `test_powertrain.py` |
| 動力系統 | 閉式解與數值解一致；匯流排功率平衡；質量 +10% → 轉速 +4.88%、軸功率 +15.37%；空氣密度縮放 ρ^-½ | `test_powertrain.py` |
| 電池 | 穩態壓降 = I(R0+R1)；RC 更新對定電流為精確解；庫侖計數 | `test_powertrain.py` |
| BEMT | 元素數收斂；係數與轉速、密度無關（無因次）；無阻力時 FM < 1（動量理論極限）；趨勢檢查 | `test_bemt.py` |
| 續航積分 | 時間步長收斂（1 s 與 0.25 s 差 < 0.2%）；電荷平衡 | `test_design_performance.py` |
| 系統識別 | 無雜訊數據精確還原；有雜訊時估計值落在宣稱不確定度內；**覆蓋率檢查**：宣稱的標準誤差要等於重複實驗的實際離散 | `test_sysid.py` |
| 端到端 | 虛擬推力台 → CSV → 系統識別，還原模型的 Ct、Cp | `test_sysid.py` |

覆蓋率檢查曾經抓到一個實際問題：推力台雜訊通常和讀數成正比，一般最小平方法的標準誤差會因此低估約 1.7 倍。現在改用 HC3 異質變異穩健標準誤差，兩種雜訊結構都通過。

## 2. 參數出處

每個參數都是一筆紀錄：數值、單位、來源類別、標準不確定度、分布、引用或說明。缺少來源就無法載入。

| 來源 | 意義 |
|---|---|
| `measured` 實測 | 自己量的，附量測紀錄 |
| `standard` 標準值 | 定義值或標準（ISA、g₀） |
| `nominal` 標稱值 | 零件的定義規格，例如 5.1 吋槳的直徑、標示的 C 數 |
| `datasheet` 規格書 | 廠商規格，必須附引用 |
| `literature` 文獻 | 論文或教科書，必須附引用 |
| `derived` 模型推導 | 由其他參數經模型計算，例如 BEMT 得到的槳係數 |
| `estimate` 工程估計 | 依零件級距的工程判斷，必須附不確定度 |
| `synthetic` 合成數據 | 只能用在驗證測試，不能出現在設計中 |

`fpvsim check` 會檢查：估計值沒有不確定度、規格書或文獻沒有引用、設計中出現合成數據，都會報警告。

陣列數據（槳葉弦長分布、OCV 曲線）以整張表標示來源。BEMT 的輸入只在載入時計算一次，它們的不確定度由 `prop.ct_scale`、`prop.cp_scale` 兩個模型不確定度乘數代表。

## 3. 不確定度

依 GUM（JCGM 100:2008）慣例：

- `u` 是**標準不確定度**（1σ），與數值同單位；`u_rel` 是相對值。
- 分布可以是 `normal` 或 `uniform`。均勻分布的 `u` 仍是標準差，半寬為 √3·u。
- 數值為正的參數，抽樣時截斷在正值。

傳遞方法採 GUM Supplement 1（JCGM 101:2008）的蒙地卡羅：每組樣本都重跑完整分析，所以非線性和不可行的情況（例如推力不足無法懸停）都會如實反映。

假設與限制：

- 參數之間視為**獨立**。
- 同型零件（四顆馬達、四支機臂）**共用一個參數**，視為完全相關，因此不會產生不對稱。不對稱效應留待飛行動力學階段處理。

規格的**符合機率**是樣本中滿足需求的比例。所有樣本都符合時，報告以三法則給出 95% 信心的單邊界限（失敗機率 < 3/n），而不是寫 100%。

敏感度採**單因子 ±1σ**（龍捲風圖）。各參數對續航、推重比、懸停油門的相對影響加總後排序，就是報告中的「建議優先量測」清單，對應真實研發中決定先量哪個數據的依據。

## 4. 單位與座標系

- 程式內部一律使用 SI 單位（kg、m、s、A、V、Ω、rad、N、W、C）。單位只在讀檔與顯示時換算，支援的單位全部明列在 `units.py`，打錯字會直接報錯。
- 機體座標為 **FRD**（x 前、y 右、z 下），與飛控韌體和航太慣例一致。原點在馬達安裝面上的馬達中心。
- 慣性張量採張量形式 I = ∫(|r|²E − r rᵀ)dm，非對角項是負的慣性積。
- 槳係數採標準螺旋槳慣例，n 的單位是每秒轉數：T = Ct·ρ·n²·D⁴，P = Cp·ρ·n³·D⁵。

## 5. 系統識別

`sysid.py` 從測試數據辨識模型參數，每個擬合都是對參數為線性的最小平方問題：

| 測試 | 模型 | 得到 |
|---|---|---|
| 推力台（靜態） | T = kT·ω²，Q = kQ·ω² | Ct₀、Cp₀ |
| 無槳空載，多個電壓 | V − I·Rm = Ke·ω；I₀ = a + b·ω | Kv、空載損耗模型 |
| 有負載 | V = Ke·ω + R·I | Ke、迴路電阻 |

標準誤差使用 HC3 三明治估計量（MacKinnon & White, 1985），在雜訊隨讀數變大時仍然正確。測試數據的 CSV 標頭必須帶單位，格式為 `名稱 [單位]`。

## 6. 可重現性

每份報告記錄：

- 程式版本與 git commit（工作區有未提交修改時會註明）
- 所有輸入檔的 SHA-256 雜湊
- 蒙地卡羅樣本數與隨機種子

用相同的 commit、輸入和種子重跑，會得到相同的數字。

## 7. 數據與智慧財產政策

- **不使用品牌與產品名稱。** 零件庫中的零件都是通用級距（例如「2306 級 1750KV 馬達」），數值標為工程估計，不代表任何特定產品。
- **不複製第三方測試資料表。** 廠商推力表、槳資料庫等可能受著作權、資料庫權利或使用條款保護，不收錄在儲存庫中。使用者可以匯入自己量測的數據。
- **規格書數值**屬於事實資訊，可以個別引用，但必須附出處，而且不大量轉錄整份資料表。
- **物理模型依公開的方程自行實作。** 方程與演算法本身不受著作權保護；引用的教科書與論文列在 `docs/models.md`。
- **不複製 GPL 等授權的程式碼。** 例如 Betaflight 採 GPL-3.0；之後實作飛控模型時，會依公開文件描述的行為自行撰寫，不複製其原始碼。若日後決定直接移植，需先確認本專案的授權相容。
- 本專案目前**尚未選定授權條款**，由專案擁有者決定。
